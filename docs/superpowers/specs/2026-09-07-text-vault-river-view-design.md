# Text Vault 河流视图设计

## 目标

把现有的“左侧搜索结果、右侧单条编辑器”改成唯一的平铺河流视图。所有匹配条目按创建时间排列、显示全文并原地编辑；键盘交互采用精简的 Vim 模态。保留现有的端到端加密、SQLite 存储、跨标签自动解锁和增量同步。

这个版本只解决文本条目的日用体验，不加入层级、附件、抽屉、删除、富文本或多视图系统。

## 方案选择

采用“普通条目是静态文本，当前编辑条目临时换成一个原生 `textarea`”的方案。

- 相比 `contenteditable`，原生 `textarea` 的换行、选区、输入法、iPhone 行为和取值边界更可预测。
- 相比所有条目常驻 `textarea`，页面节点更轻，Normal/Insert 的边界也更清楚。
- 只存在一个活动编辑器，因此键盘路由和远端同步保护都能保持简单。

没有采用 `contenteditable`，也没有采用每条始终可编辑的表单控件。

## 页面结构

页面只有四个视觉区域：

1. 顶部全宽、无文字的细状态条。
2. 右上角齿轮；展开后可修改主密码。
3. 中间可滚动的条目河流。
4. 底部可自动增高、允许折行的统一输入框。

河流中的每条记录只有一个小圆点和完整纯文本，不显示卡片边框、标题、摘要或层级。桌面和手机使用同一结构，只调整宽度、留白和字号。

条目严格按 `createdAt` 从旧到新排列。修改正文只改变 `updatedAt`，不会移动条目。查询结果仍保持该顺序。

## 模态与键盘

应用状态明确分为 `normal`、`edit`、`add`、`search` 和 `command`。保存中是状态叠加，不是可输入模式。

### Normal

- `j`、`k`：选择下一条、上一条，并把它滚动到可见范围。
- `i` 或 `Enter`：把当前条目换成原地 `textarea`，进入 Edit。
- `o`：清空并聚焦底部输入框，进入 Add；语义就是新增条目。
- `/`：底部输入框显示 `/` 并进入 Search。
- `:`：底部输入框显示 `:` 并进入 Command。
- 当页面存在非空文本选区时，`Ctrl+Enter`（macOS 为 `Cmd+Enter`）在新浏览器标签打开该文字的搜索现场。

在输入控件、密码对话框或系统组合输入期间，全局快捷键不生效。

### Edit

进入时选中条目被替换成自动增高的 `textarea`，顶部状态条为绿色。输入只修改该编辑器的草稿，不立即写入 repository，也不自动保存。

只有 `Esc` 提交：正文有变化时更新内存对象并立即发起服务器保存；正文没变化时直接回到 Normal。鼠标点页面其他位置不会退出、切换条目或提交。

### Add

`o` 后底部输入框作为新条目编辑器，顶部状态条为绿色。`Esc` 时：

- 去除首尾空白后仍为空，则放弃新增。
- 非空则用现有 memo ID 生成器创建条目，加入河流，并立即保存。

### Search

`/` 只是输入模式标记，不属于查询正文。随后每次输入都实时全文过滤河流，并把查询写入 URL fragment 的 `q` 参数。`Esc` 退出输入状态，但保留查询和过滤结果。空查询显示所有条目。

### Command

`:` 只是命令模式标记。首版只提供 `:changepwd`；按 `Enter` 执行后打开右上角齿轮使用的同一个改密对话框。密码只能在带 `type=password` 的独立字段中输入两遍，不进入底部输入框、URL或命令历史。

未知命令保留在输入框并显示简短错误。`Esc` 取消命令并回到 Normal。现有 `/s` 与携带密码参数的 `/changepwd` 删除。

## 保存与状态条

条目只在 Edit/Add 中按 `Esc` 后成为内存脏数据，随后立即提交服务器。不再使用一秒防抖自动保存，也不在窗口失焦、页面隐藏时暗中提交。

状态条含义：

- 绿色：Edit 或 Add 中，草稿尚未提交到内存对象。
- 灰色：已按 `Esc`，内存有待保存内容或服务器请求进行中。
- 与背景完全同色：服务器已确认保存，且没有待保存对象。
- 红色：保存、同步、解密或并发处理失败。

如果页面在 Edit/Add 中关闭，或 repository 仍有待保存对象，使用浏览器原生 `beforeunload` 提醒。浏览器崩溃时，尚未按 `Esc` 的草稿可能丢失；这是明确选择的 Vim 式提交边界。

## 增量同步与并发

继续每两秒拉取服务器增量，并在页面重新获得焦点时主动拉取。

- Normal 中的远端变化立即进入 repository 并重绘对应条目。
- 正在 Edit 的条目草稿独立存在，不因 repository 更新而改变屏幕中的文本。
- Edit/Add 的 `Esc` 提交先拉取增量，再保存，复用现有 generation/revision 校验。
- 极少数同一条目并发修改仍不得静默覆盖。现有冲突保全机制继续保留，但不设计常驻冲突 UI；状态条变红，远端版本作为普通保全条目出现在河流中。
- 其他标签保存不同条目后，本标签最多约两秒自动出现变化，无需刷新。

## 组件边界

- `app.js`：认证后的组合根、生命周期和各小模块装配，不承载全部键盘细节。
- 新的河流视图模块：渲染平铺条目、维护当前选择、原地编辑器和滚动定位。
- 新的输入模式模块：把按键与底部输入解析为 Add/Search/Command 动作；自身不访问网络。
- `repository.js`：增加按创建时间返回完整匹配条目的查询，不改变密文数据模型。
- `save.js`：保留显式 `save()` 与并发协调；界面不再调用延迟 `schedule()`。
- `sync.js`、`crypto.js`、Go API 和 SQLite schema：保持现有接口。
- 改密对话框：复用已有 `rewrapVault` 与 `api.rekey` 数据流。

数据库结构不变，不需要迁移。

## 错误处理

- 保存或同步失败时保持内存中的更改，状态条变红；后续同步/显式提交成功才恢复。
- 解密失败的对象继续隔离，不阻止其他条目使用。
- 改密失败时对话框保留输入状态并显示错误；成功后清空密码字段并关闭。
- 拉取期间不阻塞 Normal 导航或本地草稿输入。

## 测试

单元测试覆盖：按创建时间查询、模式转换、`j/k/i/o/:/` 路由、空新增放弃、Esc 提交、命令解析，以及 Edit 草稿不被远端更新覆盖。

浏览器测试覆盖：解锁后显示全文河流；键盘新增与编辑；实时搜索和 URL 恢复；两个标签间增量更新；新标签自动解锁；`:changepwd` 与齿轮打开同一改密流程；手机宽度下保持同一河流结构。

Go 存储/API、JS 单元测试和 Chrome E2E 必须全部通过。
